# 백업·복원 및 전환 연습

## 백업 범위와 복원 지점

`backup.mjs`는 현재 Cibo DB의 public 스키마에서 내보낸 동일한 읽기 전용 스냅샷으로 pg_dump, 업무 테이블 지문, 복사할 객체 키 목록을 만든다. OCI에서는 그 목록의 객체만 읽는다. 휴지통 원본도 복원 대상이다. 버킷 전체를 나열하거나 기존 Google Drive 자료를 검색하지 않는다.

Cibo는 업로드마다 고유한 객체 키를 만들고 이름 변경·이동·휴지통에서 객체를 덮어쓰지 않는다. 이 조건 덕분에 세션을 중단하지 않고 이 연습을 수행할 수 있다. 외부에서 원본을 덮어쓰거나 영구 삭제하는 작업이 있다면 백업이 끝날 때까지 해당 작업을 중지해야 한다.

계정과 역할, 공간 접근 부여, 공간·폴더·파일 및 변경 이력, 추출 본문·출처와 썸네일을 포함한다. 세션 및 MCP 토큰 테이블은 구조만 복원한다. 실제 서비스 전환 시에는 다시 로그인하고 MCP 토큰을 새로 발급한다. PostgreSQL 서버 전역 역할·ACL, OCI IAM, Google 설정, 환경 파일 및 키는 별도 운영 설정이다.

## 실행

준비물은 현재 커밋, 프로젝트 의존성, 실행 중인 Docker, Chrome, pg_dump/pg_restore(원본 PostgreSQL 버전을 지원하는 클라이언트), 아카이브를 저장할 사설 디렉터리다. 연습은 localhost에만 게시하는 임시 컨테이너 2개를 생성한다.

```sh
npm ci
CIBO_STATIC_EXPORT=true npm run build
mkdir -p "$HOME/.local/share/cibo-drive/backups"
archive="$HOME/.local/share/cibo-drive/backups/cibo-$(date -u +%Y%m%dT%H%M%SZ)"
node --env-file=.env scripts/recovery/backup.mjs "$archive"
node --import tsx scripts/recovery/rehearse.mjs "$archive"
```

백업은 새 디렉터리에만 쓴다. 모든 객체의 크기 및 SHA-256 검사 후 마지막에 생성되는 `manifest.json`이 완료 표시다. 정상 아카이브에는 `database.dump`, `objects/<객체 키>`, manifest가 있다. 소유자 전용 권한의 **암호화되지 않은** 사본이므로 별도 보관소로 반출할 때는 암호화한다. 자격증명, 아카이브, manifest를 Git에 넣지 않는다.

## 검증과 전환

1. 복원 도구는 덤프·객체 체크섬을 확인하고 매번 새 Docker 네트워크, PostgreSQL DB, SeaweedFS 버킷을 만든다. 원본 접속 정보 없이 실행한다. 새 DB의 전용 소유 계정으로 스키마·데이터를 복원하고 객체 키를 보존해 원본을 적재한다.
2. 업무 테이블 전체 행의 정렬된 SHA-256과 건수를 대조한다. 파일 ID·이름·부모 관계·휴지통 상태·객체 키, 계정 상태·역할·공간 부여도 이 검사에 포함된다. 대상 버킷을 나열해 예상된 키만 있는지 확인하고, 모든 원본을 다시 읽어 SHA-256을 비교한다.
3. 임시 웹·API를 복원본에 연결한다. 복원된 활성 계정의 공간 권한을 사용해 새 연습용 세션을 만들고, Chrome에서 파일을 내려받는다. 웹에서 새 MCP 토큰을 발급한 뒤 SDK 클라이언트가 같은 파일 ID로 메타데이터와 본문·출처 전 구간을 조회한다. 동일한 웹 세션 및 토큰으로 공간 권한 회수 시 403, 재부여 후 조회 재개도 검사한다. Google 재인증 자체는 이 연습의 대상이 아니다.
4. 성공 결과는 아카이브의 `verified.json`에 저장한다. 임시 API와 두 컨테이너·볼륨·네트워크는 종료 시 정리한다. 운영 트래픽과 운영 권한은 전환하지 않는다.
5. 실제 전환을 할 때는 승인한 파일 ID 목록과 목표 환경을 먼저 확정한다. 쓰기를 멈추고 최종 백업·대조 후 앱의 DB·S3 연결을 함께 전환한다. 결과가 다르면 신규 쓰기를 열기 전에 기존 연결로 되돌린다. 새 환경에서 쓰기를 이미 받았다면 변경분을 대조한 뒤 복귀한다. Google Drive 도입 자료가 별도로 있다면 승인 목록과 내보낼 형식으로 복사·비교할 때까지 기존 자료를 유지한다.
